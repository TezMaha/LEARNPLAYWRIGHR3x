Research Note: callback

A callback is a function passed as an argument to another function so it can be executed later, typically after an operation completes.

How it works

  • One function receives another function as input.
  • That input function is invoked at a later point in time.
  • Commonly used for asynchronous tasks and event handling.
  • In Node.js style, callbacks often follow (error, result) pattern.

Example

function processUser(id, callback) {
  setTimeout(() => {
    const user = { id, name: "Alex" };
    callback(null, user);
  }, 500);
}

processUser(1, (err, user) => {
  if (err) {
    console.error("Failed:", err);
    return;
  }
  console.log("Loaded user:", user);
});

Benefits

  • Simple way to run code after completion of another task.
  • Core to event-driven programming (click events, listeners, timers).
  • Widely supported across JavaScript environments and legacy APIs.

Common Pitfalls

  • Deeply nested callbacks can reduce readability (callback hell).
  • Error handling may become repetitive in large callback chains.
  • Control flow is harder to reason about than Promise/async-await code.

When to use

  • Handling events and UI interactions.
  • Interacting with libraries that expose callback-based APIs.
  • Small async tasks where introducing Promise wrappers is unnecessary.
